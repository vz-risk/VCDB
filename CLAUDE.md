# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

The VERIS Community Database (VCDB): a public, raw dataset of security incidents coded in the [VERIS](http://veriscommunity.net/) schema. It is primarily a **data repository**, not an application — the bulk of the repo is ~10,000+ per-incident JSON files plus the schema/label files that define them. The small amount of Python/R/JS here is tooling that builds, validates, and packages that data.

## Layout that matters

- **Schema & label files (repo root)** — derived artifacts, do not hand-edit downstream ones:
  - `vcdb_diff.json` / `vcdb_diff-labels.json` — the *editable* deltas applied on top of upstream `verisc.json` / `verisc-labels.json` (from [vz-risk/veris](https://github.com/vz-risk/veris)) to produce the VCDB schema. Edit these to change the schema.
  - `vcdb.json` / `vcdb-labels.json` — the generated VCDB schema and labels.
  - `vcdb-merged.json` — schema + enumerations combined; **this is the file incidents are validated against**.
  - `vcdb-enum.json`, `vcdb-keynames*.txt` — generated convenience extracts (enumerations, key lists).
- **`data/json/`** — incident records, one JSON per incident, split by validation stage (see below).
- **`data/joined/`**, **`data/csv/`**, **`data/verisr/`** — packaged outputs (zipped single JSON, CSV, R dataframe). Generated, not hand-edited.
- **`bin/`** — pipeline scripts (`fix_subsource.py`, `vcdb_to_joined.py`, analysis notebook).
- **`tools/`** — ad-hoc/legacy import & export helpers (GitHub issue import, MongoDB load, D3/JS visualizers). Not part of the core pipeline.
- **`campaigns.md`** — registry of `campaign_id` UUIDs; claim an open UUID here when linking a series of incidents.

## The validation pipeline (`data/json/`)

Incidents flow through three subdirectories — this split is the central workflow concept:

- `submitted/` — generated (usually via the VERIS webapp) but **not** auto-validated.
- `validated/` — passed `fix_subsource.py`, VERIS `rules.py` + `checkValidity.py`, and jsonschema validation against `vcdb-merged.json` with 0 errors.
- `overridden/` — failed automated validation but manually confirmed correct.

**Only `validated/` and `overridden/` feed the joined JSON, CSV, and verisr outputs.** `validated/README` warns: do not manually place files there — it is populated by the workflow only.

## Common commands

Scripts default to relative paths (`../data/...`), so run them from `bin/`.

```bash
# Join per-incident JSON into a single (optionally zipped) file
python bin/vcdb_to_joined.py -i data/json/validated,data/json/overridden -o data/joined -z

# Include the ~5,000 web-skimmer breaches in a subdirectory (normally excluded
# because they were script-discovered en masse and would bias the dataset)
python bin/vcdb_to_joined.py -i data/json -o data/joined -z -r

# Normalize plus.sub_source values
python bin/fix_subsource.py
```

There is no build/lint/test suite. The R README is generated by knitting `README.Rmd` (R + `verisr`/`ggplot2`); `figure/` holds its plot output.

## Conventions & gotchas

- Each incident JSON is keyed by `incident_id` (a UUID, matching its filename) and follows the VERIS structure: top-level `action`, `actor`, `asset`, `attribute`, `discovery_method`, `timeline`, plus a `plus.*` block of VCDB metadata (`analyst`, `analysis_status`, `dbir_year`, `sub_source`, timestamps).
- **Sampling bias is real and intentional in places.** `plus.sub_source` of `phidbr` (healthcare) or `priority` marks non-randomly-selected incidents; the web-skimmer subdirectory and the partner-sourced set noted in `data/*/NOTE.txt` are excluded from packaged outputs to avoid biasing analysis. Read the `NOTE.txt` files before treating any packaged output as a uniform sample.
- Schema changes belong in the `*_diff*.json` files, which are merged against upstream `veris` — not directly in the generated `vcdb*.json`.
- Tooling targets Python 2/3 compatibility (e.g. `vcdb_to_joined.py` notes simplejson is absent on the py2 pipeline image); some `tools/` scripts are legacy (Python 2 syntax, old `pymongo.Connection`) and reference external state.
